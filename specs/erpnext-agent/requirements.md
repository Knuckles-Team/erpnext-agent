| `CONN-ERPNEXT-AGENT-R005` | **Every Frappe business operation is its own typed tool.** Beyond document CRUD, list and whitelisted-method calls, the client exposes submit, cancel, count, get value, set value, rename, mapped follow-on document, document method, DocType field metadata, report run, link search and file upload as public methods on `Api` (erpnext_agent/api/api_client_resource.py), each mapped to one documented Frappe REST call, and the SDK serves each as one typed tool with verb-derived annotations. No action-routed tool and no alias tool is served. Caller chain: the erpnext-mcp console script loads erpnext_agent:connector (erpnext_agent/__init__.py), whose SDK tool surface (scion_sdk.mcp.method_tools.register_method_tools) registers one tool per public `Api` method. | `tests/test_frappe_operations.py::test_submit_reads_the_current_draft_then_submits_it`, `tests/test_frappe_operations.py::test_lifecycle_and_value_operations_map_to_frappe_client`, `tests/test_frappe_operations.py::test_flow_report_and_search_operations`, `tests/test_frappe_operations.py::test_doctype_meta_is_trimmed_to_fields`; aliases absent: `tests/test_api_client.py::test_auth_and_version_methods`. |
| `CONN-ERPNEXT-AGENT-R006` | **A refused call returns the server's reason.** When Frappe answers 4xx/5xx, `ApiClientBase.request` (erpnext_agent/api/api_client_base.py) raises `ErpNextApiError` whose message carries the status, `exc_type` and the decoded `_server_messages` text with markup removed, so an agent can fix the named field. The server traceback (`exc`) is never copied. Caller chain: every typed tool calls an `Api` method, which calls `ApiClientBase.request`. | `tests/test_frappe_operations.py::test_refusal_carries_the_server_reason_not_the_traceback` |
| `CONN-ERPNEXT-AGENT-R007` | **Every access contract names a served tool and only its parameters.** Each `ac:AccessContract` in erpnext_agent/ontology/access_contracts.ttl names `erpnext_list_documents` and parameters that are properties of its served input schema, for Supplier, Item, Purchase Order, Customer, Sales Invoice, Purchase Invoice, Payment Entry, Lead, Project and Employee. Caller chain: scion_sdk.access_contract.parse_access_contracts reads the file; the served server is built by scion_sdk._connector_serve.build_server. | `tests/test_access_contracts.py::test_every_access_contract_names_a_served_tool_and_its_parameters` |
